## 4. 正式なプロジェクト状態
チャット履歴を唯一の正式状態にはしない。
Git / GitHub / プロジェクト内のMarkdown等のファイルを、プロジェクトの継続性を担保する正式な記録として扱う。

今回の実験では、ChatGPTが引き継ぎ情報をMarkdown化し、Claude Codeがローカルリポジトリへ保存し、承認後にcommit・pushする運用を検証する。

## 5. ChatGPTとClaude Codeの役割

### ChatGPT
- 会話内容の整理
- 設計・分析
- 方針提案
- Claude Code用プロンプト作成
- Claude Codeの実行結果レビュー
- 次の作業の整理

### Claude Code
- Windows上のローカルリポジトリ確認
- 指定ファイルの作成・編集
- コード・ファイルの実装
- Git status / diff / commit等の実行
- 人間の承認後のpush

### 人間
- 重要な方針の承認
- 実装範囲の承認
- commit / push / 公開 / 本番反映の承認
- 実機テスト
- 最終判断

## 6. 禁止事項
- 不明な情報を推測して正式状態として記録しない
- 「ここだけ変更」の指示があった場合、指定範囲外を変更しない
- 人間の承認なしにcommit・push・公開・本番反映を行わない
- ChatGPTがClaude Codeを直接操作できるかのように扱わない
- 実際に確認していないGitHub上の状態を確認済みと報告しない

## 7. Claude Codeとの識別形式
Claude Codeへの指示は原則として以下の形式で開始する。

id="xxxxx"
【PROJECT: XXXXX】
【TASK: XXXXX】
【実装開始指示】

Claude Codeからの結果にもPROJECT/TASK識別子を付け、どの指示への回答かを明確にする。
