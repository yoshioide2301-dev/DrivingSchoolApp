# 気象解析プロジェクト｜チャット① 全履歴整理

> 作成日：2026-09-27
> 対象：気象解析プロジェクトに関して確認できる過去チャット履歴・保存済み実証資料・現在のチャット履歴
> 方針：確認できた事実と、当時の旧仕様・現在仕様を区別する。確認できない事項は推測せず「確認できない」「要確認」とする。

## 1. プロジェクトの目的

気象予報士試験の実技対策として、毎日の日本付近の実際の気象場を教材化する構想。

基本的な学習サイクルは、

**天気図を見る → 気象場を解析する → 現象を因果関係で説明する → 実際の天気と比較する**

である。

実技試験対策として、単に「低気圧がある」「雨が降る」と記述するのではなく、

- 何がどうなっているか
- それによって何が起こるか
- 地上・下層・中層・上層がどうつながるか

を重視する。

初期構想では、気象庁等の公開資料をもとに、その日の日本付近の気象場を解析し、将来的には実技形式の問題生成・AI採点・翌日の答え合わせまでつなげるMVP構想も検討された。ただし、このチャットで実際に実装された範囲は主として「毎日の気象解析レポートの取得・確認・解析フロー」の検証である。

## 2. プロジェクトの現在の位置づけ

現在確認できる正式な方向性は、**09:00 JST（00 UTC）を基準とした地上・850hPa・500hPa・200hPaの実況解析を行い、資料が揃って実確認できるまでレポート完成を急がない**という運用である。

2026-09-25に、旧「10時頃完成」運用から、完成時刻を固定しない運用へ変更された。

現在の重要原則：

- 基準時刻は09:00 JST＝00 UTC。
- 完成時刻は固定しない。
- 14時を過ぎても必要資料が揃うまで待つ。
- 正確性・完全性を完成時刻より優先する。
- 取得できない図、読み取れない数値は推測しない。
- 200hPaはAUPA20を正式採用する方針。AUXT20は保留。
- レポート完成後はスマホ通知する運用が決定された。
- 研究・取得履歴をGitHubへ記録する運用も決定された。

なお、現在のサービス名、正式なアプリ名、公開サービスとしての料金・提供形態などは、この履歴だけでは確定していない。

## 3. 現在のサービス・運用内容

現在の中心機能は、毎日の日本付近の気象場を実資料で確認し、気象予報士試験の実技を意識して解析すること。

基本解析順序：

1. 地上天気図
2. 全体概況
3. 850hPa
4. 850hPaの注目点
5. 500hPa
6. 500hPaの注目点
7. 200hPa
8. 200hPaの注目点
9. 各高度を統合した気象現象ストーリー
10. 前日からの変化
11. 必要に応じた予報資料
12. 今日の観測チェックポイント
13. 実技試験対策として覚える因果関係

重要な解析原則は「画像を実際に確認してから解析する」ことである。

画像が取得できない場合は、一般論で図の内容を補完しない。

## 4. 毎日の気象レポート運用

### レポート時刻

旧仕様：
- 09:00 JSTの実況を基準に、10:00頃までにレポートを完成させる。

現在仕様：
- **09:00 JST＝00 UTCを基準とする。**
- **完成時刻は固定しない。**
- 必要な資料が揃うまで待つ。
- **14時以降になっても待つことを許容する。**
- 正確性・完全性を完成時刻より優先する。

したがって、「14時レポート」という固定時刻のレポートが正式仕様になった、という記録は確認できない。確認できる正式変更は「14時を超えても待つ」「完成時刻を固定しない」である。

### 基準となる実況時刻

現在の正式基準：
- 09:00 JST
- 00:00 UTC

2026-09-24の実証では、この基準時刻を使用した。

### 使用する気象情報

基本セット：
- 地上天気図
- 850hPa
- 500hPa
- 200hPa

補助資料として、以下も実証された：
- 700hPa
- 高層観測（ラジオゾンデ）
- 気象衛星画像（ひまわり）
- 数値予報天気図

### レポートの構成

地上 → 全体概況 → 850hPa → 500hPa → 200hPaの順。

各図について「注目ポイント」を整理し、最後に複数高度を統合して因果関係のストーリーにする。

特に重視する因果関係：
- 下層の暖湿気
- 水蒸気・湿潤域
- 温度傾度
- 500hPaトラフ・寒気・渦度
- 200hPaジェット
- 上層発散・収束
- それらと地上低気圧・前線・降水との対応

### 最新情報の取得時刻

過去履歴から確認できる具体的な基準時刻は「09:00 JST＝00 UTC」。

2026-09-24実証では、衛星画像を09:50〜09:59 JST（00:50〜00:59 UTC）として確認している。

一方、**「最新情報を13時台に取得した」「13:50頃に取得した」という具体的な履歴は、現在確認できる保存資料・検索結果では確認できない。**

### 時刻変更の経緯

1. 初期構想では「毎朝9時基準・10時頃完成」。
2. 2026-09-24の実証でも「09:00実況 → 天気図取得 → 画像確認 → 解析 → 10:00頃レポート完成」が再現用目標フローとして記録された。
3. その後、天気図の公開・取得・確認が10時までに必ず揃うとは限らないことが問題になった。
4. 2026-09-25に、**10時完成前提を撤回し、必要資料が揃い実確認できるまで待つ運用へ正式変更**。
5. 14時を超過しても待つことを明記。
6. 完成後にスマホ通知する運用を決定。

## 6. 気象解析の基本ロジック

基本は、

**地上 → 850hPa → 500hPa → 200hPa → 統合**

である。

### 地上

低気圧・高気圧・前線・台風等の位置関係を把握。

### 850hPa

暖気・寒気、湿潤域、風、水蒸気供給を確認。

例：

暖湿気の流入
→ 温度傾度・水蒸気収束
→ 上昇流
→ 雲・降水の発達

### 500hPa

トラフ・リッジ、寒気、渦度、低気圧性循環を確認。

例：

500hPaトラフ
→ 正渦度域
→ 上昇流と結びつく
→ 下層低気圧・降水活動を支える

### 200hPa

ジェット気流と上層力学場を確認。

例：

上層発散
→ 下層からの上昇流を促進
→ 地上低気圧の発達
→ 前線・降水活動の強化

ただし、実証では200hPa断面図から水平発散・収束を直接判定できなかったため、「確認できないものは評価しない」というルールを採用した。
