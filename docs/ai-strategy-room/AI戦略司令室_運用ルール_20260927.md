# AI戦略司令室 運用ルール — 2026-09-27

## A. 基本原則
- チャットは作業場であり、唯一の正式記録ではない。
- Git / GitHub / プロジェクト内ファイルを正式な状態・履歴として扱う。
- 重要な変更は人間の承認を挟む。
- 不明な情報は推測しない。
- 作業範囲を明示し、「ここだけ変更」は文字どおり厳格に守る。
- 変更は可能な限り可逆性を保つ。

## B. ChatGPTの責任範囲
ChatGPTは主に以下を担当する。
- 情報整理
- 要件定義
- 設計
- 比較・分析
- Claude Codeへの指示作成
- Claude Codeの結果レビュー
- 次の判断材料の提示

ChatGPTは、実際に実行していない操作を実行済みとは表現しない。

## C. Claude Codeの責任範囲
Claude CodeはWindows上で、
- ファイルの作成・編集
- リポジトリ確認
- Git status / diff
- 実装
- commit
- push
等を実行できる。

ただし、commit / push / 公開 / 本番反映など重要操作は、人間の明示的承認を受けてから行う。

## D. 標準的な実行フロー
1. ChatGPTが目的と範囲を整理する。
2. ChatGPTがClaude Code用プロンプトを作成する。
3. ユーザーがClaude Codeへ渡す。
4. Claude Codeが実行する。
5. Claude Codeが結果・変更ファイル・git status等を報告する。
6. ChatGPTがレビューする。
7. 必要なら修正指示を作る。
8. ユーザーがcommitを承認する。
9. Claude Codeがcommitする。
10. ユーザーがpushを承認する。
11. Claude Codeがpushする。
12. 次のChatGPTチャットでは正式記録を基準に再開する。

## E. 引き継ぎファイルの考え方
引き継ぎ情報は、可能な限り以下のように分離する。
- CLAUDE.md：プロジェクトAIの基本憲章・作業規則
- STATUS.md：現在の実装状態
- PROJECT.md：プロジェクト概要
- DECISIONS.md：重要な意思決定
- ISSUES.md：未解決事項
- HANDOFF.md：直近の引き継ぎ

ただし、今回の検証では既存ファイルを勝手に上書きせず、テスト用の2ファイルを別名で保存する。

## F. Git操作の安全ルール
- 既存の未commit変更を勝手に消さない。
- reset / restore / stash / discardを勝手に実行しない。
- 指定外ファイルを変更しない。
- commit前に変更対象を確認する。
- push前にcommit内容を確認する。
- push後はGitHub側で反映を確認する。
